## Owner instructions on record
- 2026-10-31: "This is exactly how I want the interface to look… the exact design to be replicated" (homepage mockup).
- 2026-11-01 (F-76 confirmation): test that wrong-audience, expired and unrecognised-account tokens are rejected and that valid users reach only their own data. Wrong audience (string and array), expired, wrong issuer, missing subject, suspended account and direct-write denial are covered by `supabase/tests/f76_auth.test.sql`; "unrecognised account" was **not** covered (`ensure_user()` creates the user) and was resolved as *admit but restrict*. The Vitest UI suite that accompanied F-76 was deleted in the rebuild — re-verify before rollout.
- 2026-11-01 10:50: run both quality gates on another suitable machine before merging to `main`, and share the results. **Never disable TLS verification** to get an install through.
- 2026-11-04 (F-79 decision file): do not create another hosted database or replace Auth0 sign-in; the owner must connect the existing Supabase project through Lovable's External Supabase settings, then verify the generated configuration before applying the pending migration.
- Keep one `main` branch on GitHub; Sage 7's auto branches were cleaned up (2026-11-01). New work goes to the Lovable source repo, which mirrors into the audit repo.
