# 2026-11-13 · F-107 The OwanbeAI console

## What was missing

F-107 shipped the AI's *answering* half: the shared provider with its zero-retention gate, the
disclosure and the report control, the read-only payment investigation, the interaction log and
`open_ai_case`. Three facts were left over, and all three were found by reading the tree
rather than by the audit:

1. **`public.read_ai_cases` and `public.my_ai_interactions` were granted and called by
   nothing.** Both existed in `supabase/migrations/20261109180000_f107_owanbe_ai.sql` and
   neither had an application call site. The database could show a case queue and nobody was
   asking.
2. **No function anywhere moved `public.cases.status`.** `open_ai_case` wrote a row at `open`
   and that was the end of it. A case the AI opened could never be picked up, worked or closed.
3. **The only surface that showed OwanbeAI was inside a house.** `AiInvestigationPanel` is
   mounted in `src/features/payments/PaymentsPanel.tsx`, which lives in the **host** house. A
   platform staff member holding the `ai_investigation` grant, who was not in a host house, had
   no route to OwanbeAI at all — and the grant is a platform-staff capability, not a house one.

So F-107 was half a feature: the AI could raise its hand, and nothing could take it.

## What was delivered

- `supabase/migrations/20261113120000_f107_ai_console.sql`
  - **`public.ai_case_notes`** — one note a staff member wrote while working a case. RLS enabled
    and forced, revoked from every application role, so it is written only through the console
    function. The body carries F-60's credential guard: a card-like number is refused.
  - **`public.read_ai_cases(status)`** — the case queue: reference, subject, reason, status,
    priority, source, the opening interaction, the booking, the created and updated moments and
    the notes on the case. Refused without the `ai_investigation` grant (42501) and when signed
    out (28000). Every read is audited as `ai.cases_viewed` against the grant id.
  - **`public.read_ai_interactions(surface)`** — the answers OwanbeAI gave: the surface, the
    request, the response, the outcome, **the model that answered**, the linked case and the
    report state. This is a **sensitive read**: it is logged as `sensitive.read` against
    `ai_interactions` with a purpose and the grant id, because a list read has no single row to
    point at.
  - **`public.update_ai_case(case, status, note)`** — moves a case and optionally leaves a note.
    The legal moves live in one place, `app_private.ai_case_may_move(from, to)`: `open` →
    `investigating` / `waiting_on_customer` / `resolved` / `closed`; `investigating` →
    `waiting_on_customer` / `resolved` / `closed`; `waiting_on_customer` → `investigating` /
    `resolved` / `closed`; `resolved` → `investigating` / `closed`; `closed` → nothing. The
    audit row (`ai.case_updated`) records the from, the to and the **length** of the note — never
    the note.
  - **`public.my_ai_interactions()`** — re-created with the request summary and the model, so
    "what did the AI tell me?" is answerable by the person who asked. No grant is needed for
    one's own answers and nobody else's answers are in the result.
- `supabase/tests/f107_ai_console.test.sql` — the SQL suite (written, unexecuted).
- `src/features/ai/console-contracts.ts` — the case statuses, the legal moves, the labels, the
  disclosure and the update schema. It mirrors the database's transition rule so the form only
  offers a move the server will accept; the database stays the authority.
- `src/features/ai/console.server.ts` — the server boundary. The caller's own token is
  forwarded to the database; there is no service-role path in the file. Each database refusal
  becomes its own word: 42501 → "for platform staff who hold the AI investigation grant", P0002
  → "we could not find that case", 22023 → the refusal that caused it.
- `src/features/ai/console.api.ts` — the browser boundary, with the error codes and the copy.
- `src/features/ai/AiConsolePanel.tsx` — one panel in three sections: **your own answers**
  (every signed-in person), **the cases** (staff) and **the answers** (staff). The one form
  works a case: a status select limited to the moves the case may make, a note, save and
  cancel. Loading, empty, refused and error states are all present.
- `src/routes/ai.tsx` and `src/routes/api/ai/{cases,answers,mine,case}.ts` — the page and the
  four routes. The page is **outside both house shells**, like `/observability`, so a grant
  holder does not need a house to reach it.
- `docs/decisions/f107-ai-console.md` — the decisions above, in one place.

### Working a case changes the case and nothing else

The console has no money path and no path to the money path. `update_ai_case` writes a status
and a note; it touches no ledger, no fund pool, no booking and no payment. The AI's own
`investigation_only` identity (F-46) has no `EXECUTE` on any of the four console functions and
no table grant on `cases`, `ai_interactions` or `ai_case_notes` — the console belongs to a
person, not to the AI.

A refused move writes nothing at all: an illegal transition, an unknown status, an unknown
case, an empty note and a note carrying a card-like number are each refused before any write,
so no status change, no note row and no audit row is left behind.

## Not done, and why

- **The migration is not applied to any database.** It has never run. The console is unverified
  until the CI database job and the audit have run.
- **The console does not notify anyone.** A house alert on a case move belongs to the feature
  that owns notifications; inventing one here would be a second path to the same inbox.
- **The console does not re-run an investigation** and does not resolve a dispute. F-16 owns the
  dispute flow and will extend this same `cases` table rather than re-create it.
- **The zero-retention gate is open** on the owner's 2026-11-10 confirmation, so OwanbeAI can
  be used once the migrations are applied. The platform stores the owner's confirmation, not the
  contract, so the evidence gap behind F-65 stays open (`docs/open-questions.md` Q18).
