# Owner decision: TanStack Start runtime and Paystack are approved architecture

Recorded so Sage 7 accepts the current stack instead of flagging it as an unapproved addition.
Full text in `docs/adr/0003-tanstack-start-runtime-and-paystack.md`.

The project runs on TanStack Start (`@tanstack/react-start` 1.168.60, `@tanstack/react-router`
1.170.41, React 19.2, Vite 8.1, Tailwind 4 with tokens in `src/styles.css` `@theme`, SSR through a
nitro/Cloudflare build). This is Lovable's current workspace template (`tanstack_start_ts_current`),
and the app is built and published on Lovable, so the runtime follows the platform. Ported pages keep
their React-Router-shaped imports through the adapter in `src/lib/router.tsx`. Bun is the package
manager; tests are Vitest 4 plus the SQL suites in `supabase/tests`.

Payments use **Paystack, not Stripe** — the owner's explicit instruction (commit `9b4dec5`).
`PAYSTACK_SECRET_KEY` / `PAYSTACK_PUBLIC_KEY` replace the Stripe names, webhooks are HMAC-SHA512
verified at `POST /api/public/paystack/webhook`, and `checkEnvIsolation()` keeps live and test keys in
their own environments. The stack tables in `AGENTS.md` and `blueprint/` were updated to match; the
blueprint is regenerated by Sage 7 syncs, so this decision is the durable record — please carry Paystack
into the next blueprint compile.

The `.github/workflows/` files (`verify.yml`, `mirror-to-owanbe.yml`) were built at the owner's explicit
request and are approved infrastructure, not unsanctioned additions.

Still needing an owner decision: shadcn/ui + Radix arrived with the template and no ADR covers them
(ADR 0001 predates them, and `AGENTS.md` requires a recorded decision before adding a UI kit).
